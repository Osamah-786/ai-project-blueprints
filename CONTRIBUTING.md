# Contributing

Keep changes focused, accurate, and useful.

- Use simple, natural English.
- Give each file a clear purpose and avoid repeating the same rules everywhere.
- Use placeholders such as `[PROJECT_NAME]` when details are unknown.
- Do not invent provider capabilities, prices, free-tier limits, passwords, or API keys.
- Separate confirmed facts from assumptions and open questions.
- Never mark a check complete without evidence.
- Keep agent-specific instructions accurate for the target tool.
- Check links, headings, code fences, paths, and consistency before submitting.
- Add a template only when it solves a repeatable need.
- Do not put real secrets or private data in examples.
